# sing-box Auto Setup (VLESS XTLS-Reality + Hysteria2)

سكربت ومعمارية عملية لإعداد سيرفر بروكسي/VPN خاص وخفيف على **Ubuntu 24.04 LTS** باستخدام نواة **`sing-box`** الرسمية، يجمع بين بروتوكولي **`VLESS + XTLS-Reality`** (`TCP 443`) و **`Hysteria2`** (`UDP 443`) في خدمة واحدة دون لوحات تحكم ثقيلة أو فتح منافذ إدارة إضافية، مع اعتماد **`v.whatsapp.net`** كنطاق تمويه (`SNI`) افتراضي.

## المزايا الرئيسية
- **خفة وأداء عالٍ:** تشغيل مزدوج (`TCP 443` + `UDP 443`) ضمن خدمة `sing-box` الرسمية باستهلاك ذاكرة منخفض جداً.
- **تمويه وتحقق تشفيري (`VLESS + XTLS-Reality`):** مصافحة `TLS 1.3` مطابقة لنطاق `v.whatsapp.net` بتدفق `xtls-rprx-vision` وتحقق كامل عبر المفتاح العام (`PublicKey`).
- **سرعة واستجابة (`Hysteria2`):** نفق `QUIC / HTTP-3` على `UDP 443` للأداء العالي على الشبكات المزدحمة أو ذات فقدان الحزم.
- **تسريع شبكة تلقائي:** تفعيل خوارزمية **`BBR`** في نواة Linux لثبات السرعة وتقليل التقطيع.
- **فحص مسبق وحماية المفاتيح:** يتحقق السكربت من دعم النطاق لـ `TLSv1.3` و `ALPN: h2` وصحة الشهادة قبل الكتابة، ويحفظ الأسرار محلياً بصلاحية `600` في `/etc/sing-box/creds.env` مع طباعة روابط ورموز `QR` في التيرمنال.

## المتطلبات المسبقة (جدار الحماية السحابي)
قبل تشغيل السكربت، افتح المنافذ التالية فقط في جدار الحماية لدى مزوّد السحابة (مثل AWS Security Group أو Oracle Cloud أو غيرها):

| البروتوكول | المنفذ | المصدر (Source) | الاستخدام |
| :--- | :--- | :--- | :--- |
| `TCP` | `443` | `0.0.0.0/0` | `VLESS + XTLS-Reality` |
| `UDP` | `443` | `0.0.0.0/0` | `Hysteria2 (QUIC / HTTP-3)` |
| `TCP` | `22` | `My IP` (عنوانك فقط) | إدارة السيرفر عبر `SSH` |

## التشغيل السريع (خلال دقيقة)

1. اتصل بسيرفر Ubuntu عبر `SSH`، ثم شغّل السكربت بصلاحية `root` (يعتمد `v.whatsapp.net` افتراضياً):

```bash
chmod +x setup-vpn.sh
sudo bash setup-vpn.sh                # النطاق الافتراضي: v.whatsapp.net
sudo bash setup-vpn.sh example.com    # نطاق تمويه مخصص (المعامل الأول)
```

> ملاحظة: عند إعادة تشغيل السكربت لاحقاً لتغيير النطاق فقط، يحتفظ السكربت تلقائياً بمفاتيحك القديمة (`UUID` و `Keypair`) ويحدّث النطاق والشهادة فقط.

## ضبط تطبيقات العميل ومشاركة الاتصال

### 1. على iOS (تطبيق SNI Tunnel)
- استورد الإعدادين عبر مسح رمز QR مباشرة من التيرمنال.
- في `Settings` ← `Anti-censorship`:
  - أوقف تفتيت حزم `ClientHello` (`Fragment`)؛ لأن `XTLS-Reality` يبني مصافحة `TLS` طبيعية وتفعيل التفتيت يسبب أخطاء اتصال.
  - أوقف `Global SNI Override` ما دام النطاق `v.whatsapp.net` مدمجاً داخل الرابط نفسه.
- في `Settings` ← `Network engine`:
  - اترك `Multiplexing` مغلقاً (إلزامي مع تدفق `xtls-rprx-vision`).
  - يُنصح بمحرك `gVisor` مع `MTU 1500` (أو `1280` عند التقطيع على شبكات الجوال).
- مشاركة نقطة الاتصال (Hotspot Sharing):
  - إذا فعّلت مشاركة البروكسي، أوقف `Share on Local Network` (`LAN / Wi-Fi`) أو فعّل `Proxy authentication` بكلمة مرور حتى لا يستخدم غرباء على نفس الواي فاي سيرفرك ويستهلكوا حصة البيانات.
  - عند ربط جهاز آخر بنقطة اتصال الآيفون: استخدام تطبيق `SNI Proxy` يمرر كامل حركة الجهاز بما فيها الألعاب و`UDP` دون إدخال بروكسي يدوي، بينما البروكسي اليدوي (`Manual Proxy Setup`) يقتصر على التطبيقات التي تتبع بروكسي النظام ولا ينقل `UDP` أو معظم الألعاب.

### 2. على Android
- **`SNI Tunnel` (الخيار الأول):** استورد الروابط عبر مسح رمز QR مباشرة من التيرمنال.
- بدائل مدعومة: `v2rayNG` أو `NekoBox` مع الاستيراد عبر مسح رمز QR.

### 3. على Windows (بدون استنزاف الباقة)
- فعّل `Metered connection` لنقطة الاتصال في إعدادات شبكة ويندوز وأوقف تنزيل التحديثات عبر الاتصالات المحدودة لتقليل الاستهلاك الخلفي.
- شغّل عميل `v2rayN` بصلاحية المسؤول (`Run as administrator`)، واستورد الرابط (`vless://` أو `hy2://`)، واضبط `System proxy` على `Clear system proxy`، و`Routing` على `Global`، وفعّل `Enable Tun` لتمرير كامل حركة النظام عبر النفق.

## تنبيهات أمنية وتكلفة
- **لا تنشر الروابط أو صور QR علناً:** تحتوي على مفاتيح الوصول الخاصة بسيرفرك.
- **مراقبة حصة البيانات:** في الخطط السحابية المجانية (مثل AWS Free Tier بحد 100 GB شهرياً للبيانات الصادرة)، فعّل تنبيهات الفواتير (`Budget Alerts`) وراقب الاستهلاك الشهري.
- **إعادة التشغيل:** استخدم `Reboot` بدلاً من `Stop/Start` للحفاظ على عنوان IP العام للسيرفر إن لم يكن لديك IP ثابت.
